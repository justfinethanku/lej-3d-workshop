# LEJ/Fleet Workshop data contract

This reference applies when the user's configuration selects Jonathan's Workshop service. Other users can adopt its evidence and preservation principles without using Fleet. It is a description of the existing service, not a requirement to build a database for ordinary modeling. Inspect current API/schema before authorized writes; implementation details can change. Public catalog reads do not grant owner access.


The website repository is `justfinethanku/limited_edition_jonathan`; its current `docs/current/print-filament-contract.md` and testing runbooks describe the implementation. Use a task worktree for code changes; do not edit another agent’s checkout. Secrets come only through `fleet get`; never log them or write an ad-hoc env file.

Read `print_inventory_catalog` for products and availability, and `print_inventory_components` for purchase allocation. Open/sealed product counts are authoritative. Spool records allocate subsets; untracked remainder plus active tracked units reconciles to each total. Identifying a spool never creates extra stock. Unknown totals must be explicitly reviewed before allocation. Changing an identified unit’s open/sealed/depleted state is an explicit stock edit; releasing its tracking returns its allocation while retaining history. Never add installed hotend counts to owned totals.

Filament tables: `print_filament_families`, `print_filament_item_families`, `print_filament_guidance`, `print_filament_spools`, `print_filament_observations`. Profile tables: `print_profiles`, `print_profile_versions`, `print_profile_compatibility`, `print_profile_usages`, `print_profile_validations`. Physical validation attestations append against an exact profile usage and inspected successful print; publishing does not itself establish tested status. Inspect the live schema before constructing SQL; do not guess a missing field.

Prefer the same-origin owner API for writes: `/api/print-filament`. `save_spool` requires current item version and spool version for edits. `add_observation` requires current spool version; server supplies the recorded time and actor. `save_profile_version` edits a draft and its compatibility atomically; publishing freezes it and requires verified files. `link_profile` links a published version to a draft release or planned/in-progress attempt, with current parent version and a preserved settings snapshot. Use the reviewed atomic RPCs for authorized agent-side DB writes; do not bypass them with piecemeal stock updates.

Current observation is the newest observed-time reading among non-superseded entries, with recorded time as a tie-breaker. Late entry of an older reading does not replace newer evidence. `remaining_g` on the old product record is an unallocated legacy note: never fan it out onto physical spools. Sum grams only for identified observed active spools and display observed-unit coverage, unknown units, estimate versus measurement, and observation age.

Private `print-library` storage and `print_library_files` preserve files for exactly one release, attempt, or profile version. 50 MiB per-file limit currently applies. Preserved published files, profile metadata, dependencies, compatibility, and usage snapshots are immutable. Corrections create a new version. Sharing selects exact file IDs, checks revocation on every download, and never enables writes. No permanent public bucket or executable G-code adaptation for different hardware.

## Inventory details preserved from the workspace

Use `print_inventory_catalog` for public products, filament, equipment and supplies. Product availability is sealed plus open count; equipment uses `quantity_on_hand` and `unit_label`. NULL means not counted, not zero. Receipt-default counts are editable history-derived starting values, not physical observations. Never rerun defaults over owner edits. Spending belongs to purchase lines before joining component allocations; bundle children must not multiply original purchase costs. Printers, AMS units, hotends and confirmed accessories may be separate rows linked to one purchase. Installed parts are included in ownership, not added again. Preserve unknown accessory quantities/specifications.

Inventory tables include `print_inventory_items`, `print_inventory_orders`, `print_inventory_purchase_lines`, `print_inventory_components`, and append-only `print_inventory_changes`. Product spool totals remain authoritative; tracked plus untracked reconciles to those totals. `stock_checked_at` blank means not physically reviewed. Public responses exclude prices, order history, private receipt/account links and sensitive owner details at the server boundary. Orders are owner-only; public product links replace private receipt links for visitors without deleting owner evidence.

## Print library and releases

Discover existing `print_library_projects` before creating duplicates. Related tables are `print_library_releases`, `print_library_files`, `print_library_attempts`, `print_library_materials`, `print_library_shares`, `print_library_share_files`, and append-only `print_library_events`. Preserve local source paths, SHA-256, byte lengths, snapshot date, version label, change notes and status. Verify downloaded bytes; use checksum-identical content for reuse, never filename similarity. Migration/deduplication is not authorization to delete or move originals.

Drafts can change. Sealing `ready_to_print` freezes identifying metadata and files; corrections need another release. Latest release and last successfully printed release differ. `physically_verified` requires an inspected successful print linked to that exact release. Historical attempts may remain `source_match=unresolved`; retain original task ID and evidence. Save original error code/message without inventing missing data. Material `estimated_g`, printer `reported_g`, and `confirmed_g` remain separate and never silently deduct inventory. A proposed material is not an evidenced inventory match.

Use `print_library_save_attempt` for atomic version-matched attempt/material updates, and reviewed share RPCs for attributed audit. Share exact verified file IDs; token hashes only, expiry/revocation checked for every download. Keep the bucket private. Profile selection and resolved settings snapshots attach only to drafts or planned/in-progress attempts; do not rewrite sealed releases or invent historical usage.

## Guidance and physical attestations

Link manufacturer guidance explicitly to products/families, preserving source/date/scope/original units. Keep manufacturer, shipped default, research gap and owner-inspected evidence distinct. Public profile compatibility is an immutable published baseline; append `print_profile_validations` against the exact usage and inspected successful attempt. `add_profile_validation` checks current profile/attempt versions and matching printer/nozzle/plate evidence. Publishing does not create a tested claim.

Use current same-origin owner APIs or reviewed atomic version-checked RPCs for authorized changes. Conflicts require reload and reconciliation. Record observation amount/unit, observed time, source, evidence and attribution; only identified consumable units receive readings. Percent is estimated, not measured. Corrections stay on the same spool and cannot branch or cycle. No background collection, automatic stock deduction or printer synchronization is implied by planning.
